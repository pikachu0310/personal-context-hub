# 会議中に、案が動き出す。

IDOの展示では「会話を記録する」から一歩進めて、**話した案を作り、触った感想で、その場で直す**ところを見せます。会議の文脈は、試作するCodexと同じタスクの追加依頼へ引き継がれます。

## 主役にする場面

VRゲームの企画会議で、ワープ移動と連続移動のどちらを選ぶか迷っています。二つの方式を同じコースで動かすブラウザ用の試作を作り、並べて触ります。「連続移動が速すぎる。半分にして」と伝え、同じタスクの修正を再び触って確かめます。会議の出口が、次回までの宿題から、比較できる試作と次の判断に変わる場面です。

生成済みサンプルは、同じコースにある光る目標を3つ集める短いチャレンジです。方式ごとの進行表示とリセットがあり、単に移動を眺めるだけでなく、来場者が目標へ向かって操作しながら違いを感じられます。

この試作はブラウザ上での操作比較です。VR機器での快適性・酔いや、画面共有をAIが見て修正する経路は、このデモの実演範囲に含めません。

## 発表がなくても伝わる見せ方

常に触れる完成版を一つ開いておきます。新しい生成を待つ間にも、来場者は二つの移動方式を試せます。事前生成したものは「この会話から生成した試作」と紹介し、その場で生成したものとは区別します。

1. **入口の一言:** 「この二つ、どちらの移動がいいですか？　触ってみてください。」
2. **体験:** 来場者が二つを操作し、違和感を一つ挙げます。
3. **修正:** プレビュー下の入力欄に感想を入れ、「このタスクに修正を依頼」を押します。作業中は別の案を試すか、元の会議の議事録を見せます。
4. **結果:** 「修正が届きました」から最新版を開き、「修正前と比べる」で前後の版を並べて同じ操作を試します。締めの一言は「今の感想まで含めて、同じ会議の続きを作っています。」

プレビューを開くと、その時点のHTMLを端末内に保存します。同じ内容は重複保存せず、タスクの実行ごとに直近12版を保持します。版を選び直しても、実際の作業ファイルは巻き戻りません。PCでは前後を横並び、小さい画面では縦並びで操作できます。「大きく表示」で画面を広く使えます。修正を待つ間も前の版を触れ、進行状態と依頼からの経過時間を見られます。

「展示表示」では操作の流れを添えて全画面で試作を開きます。「この表示のリンクをコピー」で、この端末から直接試作へ戻るURLを保存できます。公開用の共有URLではありません。作品が横並びで狭く感じる場合は「切り替えて見る」を使い、同じ幅で修正前と現在の版を行き来できます。リハーサル起動時にも、直接開ける展示URLを `exhibitUrl` として出力します。

30秒で紹介するなら、次のように話せます。

> 会議で案が出ても、試すのは会議の後になりがちです。IDOは会議に参加し、その文脈を使って試作を進めます。たとえば、VRゲームの移動方式を二つ作って、その場で触って比べる。速すぎると感じたら、同じタスクに伝えて直す。話して、作って、触って、直す。この一周を、会議の中で進めるエンジンです。

別の題材なら、イベント申込画面の二案を実際に入力して比べる、協力ゲームの仕掛けを小さく作って遊び方を確かめる、という流れにも使えます。展示では題材を一つに絞ると、会話と変更のつながりが伝わりやすくなります。

## 開発環境でのリハーサル

Discordを使わずその場で始める場合は、Clientのプロジェクトで議事録を開き、「会議へ発言する」から案を文章または短い録音で伝えます。常時聞き取りはDiscord側、ブラウザ側はボタンを押して区切った発言を送る方式です。自動で受け付けたタスクは同じプロジェクトに現れます。生成中は既存の試作を触り、完成したタスクのプレビューへ移ります。

APIなしで操作だけを試す場合は、[生成済みの比較モック](../examples/meeting-locomotion/index.html)をブラウザで開けます。合成音声から生成したものに、同じタスクで初期速度と表示の修正を加えたサンプルです。AIへの追加依頼まで動かすには、以下のリハーサルを起動します。

ビルド済みのNode.js 24環境で実行します。`OPENAI_API_KEY` と、既存のCodex認証ファイルを指す `IDO_EVAL_AUTH_FILE` が必要です。この操作は実API・実Codexを使います。合成音声を文字起こしし、隔離したEngine/Clientで会議処理と試作を実行します。Discordへの接続・投稿はありません。

```sh
IDO_LIVE_EVAL=1 IDO_EVAL_AUTH_FILE=/path/to/auth.json \
  node --env-file=/path/to/private.env --import tsx scripts/meeting-demo.mjs
```

生成が終わると、ターミナルに `demo-ready` とClientのURLが表示されます。既定は `http://127.0.0.1:4342` です。タスクの「試作を開く」から操作できます。Ctrl+Cで終了し、生成物と会話履歴は残します。再開するときは、表示された `directory` を `IDO_DEMO_DIRECTORY` に指定して同じコマンドを実行します。再開では試作を生成し直しません。ポートは `IDO_DEMO_ENGINE_PORT` / `IDO_DEMO_PREVIEW_PORT` / `IDO_DEMO_CLIENT_PORT` で変更できます。

Clientの単体HTMLプレビューは、作業フォルダー内の深さ3階層まで・24ファイル・各2MiB以内を対象にします。外部通信や外部ファイルを必要とするアプリには、既存の開発サーバープレビューを使います。HTMLは隔離したフレームで動き、会話画面や他のローカルサービスへアクセスできません。
