# 自分のCodexをDiscordにつなぐ

参加者のPCに **IDO Agent** をインストールし、1つのDiscord Botからタスクを受け取ります。コードとPRはGitHub、相談と進捗はDiscord Forumで共有します。OpenAIのログイン情報を主催者へ渡す必要はありません。

## Windowsで参加する

1. Discordで `/ido agent setup` を選び、**IDO Agentをダウンロード**からインストーラーを取得します。ボタンがない場合は、主催者が配布する同じ版のインストーラーを使用してください。
2. ダウンロードした `IDO-Agent-Setup-<バージョン>.exe` を開き、インストールを完了します。**インストール後は自動起動しません。** Windowsのスタートメニューで **IDO Agent** を検索して開いてください。Node.jsとCodexは同梱されています。作業用のGitと対象リポジトリは、自分のPCに用意してください。Gitの入手先はアプリの接続設定から確認できます。
3. **OpenAIでログイン**を押し、OpenAI公式の認証ページでログインします。接続用に分離した認証保存先を使うため、最初の1回はログインが必要です。次回以降は接続用Codexの認証を再利用します。
4. Discordで `/ido agent connect` を選び、本人だけに表示された `ido1.` から始まる参加情報をコピーします。アプリの「Discordの参加情報」に貼り付け、**参加情報を読み込む**を押すと、接続先と参加コードが設定されます。
5. 接続先を確認して作業フォルダーを選び、**エージェントを接続**を押します。「接続中」と表示されればタスクを受け取れます。

参加情報は5分・1回限りです。他人に共有しないでください。読み込みだけでログイン・接続・実行は始まりません。作業フォルダーと権限は本人が選び、参加情報の読み込み時には自動実行・外部通信の選択を解除します。接続中の設定は上書きしません。

## 次回の起動・再接続

Windowsのスタートメニューで **IDO Agent** を検索 → **接続設定** → 接続先と作業フォルダーを確認 → **エージェントを接続** の順に進みます。同じ接続先の有効な登録が残っていれば、インストールや参加情報の発行を毎回行う必要はありません。接続先の変更や登録失効時は、Discordで新しい参加情報を発行してください。

## アプリが開かない・接続できない場合

- Discordのダウンロードボタンは入手先を開きます。アプリはスタートメニューから起動してください。ブラウザのlocalhostページは使いません。
- スタートメニューに見つからなければ、ダウンロードしたインストーラーでインストールが完了しているか確認します。主催者のPCのファイルパスは、別の参加者のPCからは開けません。
- 参加情報が期限切れなら、アプリを開いてから `/ido agent connect` を実行し、新しい情報をコピーします。アプリの **Discordの参加情報** に `ido1.` から始まる文字列全体を貼り付けてください。
- 接続できない場合は、主催者にBotと公開WSS接続先の稼働を確認してもらいます。Botが停止中でもアプリは起動できますが、Discordのコマンドやエージェント接続は利用できません。
- 旧ブラウザ版を使っていた場合は、旧画面の **接続を停止** を押し、旧起動プロセスを終了してからアプリへ切り替えます。

## タスクを見る・停止する

左の一覧でタスクを選ぶと、依頼内容・進捗・結果・作業場所が表示されます。検索と「進行中」「終了」で絞り込めます。既定では受信したタスクは **承認待ち** になり、本人が **このタスクを実行** を押してから開始します。90秒以内に確認できない場合や **実行しない** を選んだ場合は実行しません。同じIssueへの追加指示も、その都度確認します。

実行中のタスクは詳細の **タスクを停止** で停止できます。**接続を停止** はWorker全体を切断します。ウィンドウを閉じるか **アプリを終了** を押すと、このアプリの接続・ログイン処理・実行タスクを停止してから終了します。トレイ常駐・自動起動は行いません。Windowsのタスクマネージャーには **IDO Agent** と表示され、作業中は子プロセスのCodexやGitなども動作します。

このアプリのタスク一覧・進捗はメモリー内で保持し、終了時に消去します。変更したファイルと分離worktreeは端末に残ります。実行ログは各タスク直近30件に制限しています。

接続設定の **Codex App・CLIの直近タスクも表示する** を選ぶと、このPCの通常のCodex保存先から、直近7日・最大30件のタスク名と作業場所を参照します。この情報はDiscordへ送らず、会話本文・認証ファイルは読みません。外部プロセスの実行状態は取得できないため、**外部で管理・状態未確認** と表示します。停止は元のCodexで行ってください。WSL・別のPCの履歴は対象外です。Codexの内部データ形式が変わった場合は、参照表示を利用できないことがあります。

信頼できるチームでは、接続前に自動実行を選べます。タスクのシェルからの外部通信とライブWeb検索は既定で無効です。依存取得などが必要な場合だけ外部通信を選んでください。これらの許可は次回起動へ引き継ぎません。OpenAIとのモデル通信とBotとの連絡は別に行います。

登録自体を失効させる場合はDiscordの `/ido agent disconnect` を使います。OpenAIからのログアウトとは別の操作です。

## DiscordからIssueタスクを作成・停止する

参加条件（必要に応じてサーバーの役職）を満たし、自分のエージェントを登録した参加者は、`/ido task` で依頼を送れます。Bot内部にIssueタスクを登録し、設定済みのDiscord Forumに対応スレッドを作成します。これはGitHub Issueを自動作成する操作ではありません。

一般参加者の音声・通常の会話から、発言者本人のエージェントへIssueを作成する経路は未対応です。本人への割り当ては上記コマンドを使ってください。既存の操作担当者向けの会話タスク化とは別の機能です。

各参加者の依頼は本人のエージェントで実行します。切断中は待機し、他人のPCやBotホストへ自動で振り替えません。接続画面でタスクごとに実行を確認するか、接続前に自動実行を明示的に選んでください。

自分のタスクは `/ido stop` でIDを指定するか、スレッド内の停止ボタンで停止できます。Issueスレッドに停止指示を書いても停止できます。停止は待機中の依頼にも実行中のエージェントにも伝わります。参加条件を失った後も、自分のタスクの停止は可能です。他人のタスクやBot全体の操作は、設定済みの操作担当者に限定します。

## 認証と作業場所

### 実行権限と一時停止

Windowsでは、作業フォルダーを選び、接続前に **Windowsサンドボックスを設定** を押してください。Windowsの管理者確認が表示されます。設定できない端末では管理者に相談してください。読み取り専用のままの場合、タスクは設定の案内を表示して停止します。

タスクの開始承認に加え、Codexが追加の許可を求めた操作はタスク詳細にコマンド・作業場所・理由を表示します。内容を確認して、その操作だけ許可または拒否してください。未回答は5分で拒否されます。無制限の実行権限には切り替えません。

実行中のタスクは **一時停止** で処理の終了を待ち、外部通信の許可を見直して **再開** できます。同じタスク・作業場所・保存済みCodex会話を引き継ぎます。実行済みの変更や外部への投稿は取り消しません。**タスクを停止** は終了操作です。終了・失敗済みのタスクは表示される `/ido follow` の案内から再依頼してください。アプリを閉じた後に一時停止状態を自動復元する機能はありません。

タスクマネージャーでは **IDO Agent**（詳細タブでは `IDO Agent.exe`）を確認できます。接続設定にもアプリのバージョン・プロセス名・PIDを表示します。Codexの子プロセスは別の名前で表示される場合があります。

- OpenAIの認証は同梱の公式Codexが行い、認証情報はそのPCの接続用 `codex-home` に残します。この接続アプリはパスワード入力欄を持たず、認証ファイルも読みません。接続用Codexでは個人のユーザー設定を共有せず、Apps・フック・プラグインなどの自動利用も無効にします。
- Botとの接続鍵は別物です。WindowsではCurrentUser DPAPI、Linuxでは所有者だけが読めるファイルへ保存します。中央Botには公開鍵と接続トークンのハッシュだけが残ります。
- 接続先、作業フォルダー、表示名は端末内のアプリ設定に保存します。参加コードや認証情報はそこへ保存しません。
- 作業は指定したリポジトリの分離worktreeで実行します。GitHubへのアクセスが必要なら各自のGit認証も事前に用意してください。Botへの参加だけで他人のリポジトリ権限は付与されません。

公式の認証方式は[OpenAIのCodex認証ガイド](https://developers.openai.com/codex/auth/)を参照してください。

CLIから直接接続する場合は `--allow-automatic` または `PERSONAL_CONTEXT_AGENT_ALLOW_AUTOMATIC=true` による自動実行への明示的な同意が必要です。CLIは `CODEX_HOME` の認証を使用します。本人確認を挟んで実行したい場合はIDO Agentを使ってください。

## 主催者が用意する接続先

別のPCから参加するには、Bot側のWorker Gatewayへインターネットから届く `wss://` 接続先が必要です。これはタスク・進捗・回答の暗号化された通信路であり、OpenAIへのログイン先ではありません。参加者側にVPNの導入は必要ありません。

主催者のPCを使う場合は、[PC運用の構成](discord-agent-public-deployment.md#主催者のpcで運用する)に沿ってGatewayだけをトンネル経由で接続します。公開サーバーを使う場合はHTTPSリバースプロキシから同じホストの `127.0.0.1:8787` へWebSocketを転送します。どちらもBotのローカル設定には次を指定します。

```dotenv
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_ENABLED=true
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_HOST=127.0.0.1
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_PORT=8787
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_PUBLIC_URL=wss://agents.example.com/workers
PERSONAL_CONTEXT_VOICE_AGENT_JOIN_GUIDE_URL=https://example.com/agent-join
PERSONAL_CONTEXT_VOICE_AGENT_DOWNLOAD_URL=https://example.com/IDO-Agent-Setup-0.2.1.exe
PERSONAL_CONTEXT_VOICE_WORKER_ALLOW_GUILD_MEMBERS=true
PERSONAL_CONTEXT_VOICE_WORKER_ENROLLMENT_ROLE_IDS=
PERSONAL_CONTEXT_VOICE_ALL_PARTICIPANTS_OPERATE=false
PERSONAL_CONTEXT_VOICE_AUTONOMOUS_TASKS=false
PERSONAL_CONTEXT_VOICE_CODEX_SANDBOX=workspace-write
PERSONAL_CONTEXT_VOICE_OPERATOR_IDS=<Bot全体の作業操作を許可する担当者ID。不要なら空欄>
```

`agents.example.com` は実際の公開接続先に置き換えます。プロキシはWebSocket Upgradeと長時間接続を許可し、公開側では有効なTLS証明書を使ってください。公開対象はWorker Gatewayだけです。参加者用のローカル接続画面やCodexの認証コールバックを公開してはいけません。

公開先のDNS・証明書・プロキシ設定はホストごとに必要です。このリポジトリだけで公開URLが発行されるわけではありません。Botを起動してから実際に異なるPCの2人が接続し、個別のタスク配信・再接続・登録解除を確認してください。

[公開運用の境界と設定例](discord-agent-public-deployment.md)も確認してください。公開URLを指定した状態で、参加者全員の無条件操作・ホストのsandbox無効化・自律的タスク作成を有効にすると起動を拒否します。
