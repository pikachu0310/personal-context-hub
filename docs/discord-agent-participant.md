# 自分のCodexをDiscordにつなぐ

参加者のPCでCodexを動かし、1つのDiscord Botからタスクを受け取ります。コードとPRはGitHub、相談と進捗はDiscord Forumで共有します。OpenAIのログイン情報を主催者へ渡す必要はありません。Web画面は接続と実行確認に使い、作業は各自のPC内で行います。

専用のネイティブアプリをインストールする必要はありませんが、Node.js・Gitとこのリポジトリの接続用プロセスは必要です。ブラウザだけでローカルPCの作業を自動実行する方式ではありません。

## Windowsで参加する

1. 作業するPCのDiscordで `/ido agent connect` を選び、**① 接続用.cmdをダウンロード**を押します。表示された添付ファイル `Connect-Agent.cmd` を保存してください。`/ido agent setup` からも取得できます。
2. 保存した `Connect-Agent.cmd` をダブルクリックします。Node.js 22以降やGitがない場合は、確認後にWindows Package Managerでインストールできます。利用できないPCでは案内に沿って手動で用意します。初回の依存パッケージ準備後、ブラウザに接続画面が開きます。接続アプリ用にこのリポジトリをcloneしたり、GitHubにログインしたりする必要はありません。作業対象のリポジトリは自分のPCに用意してください。
3. **OpenAIでログイン**を押し、OpenAI公式の認証ページでログインします。普段のCodexの設定を引き継がない接続用の保存先を使うため、最初の1回はログインが必要です。次回以降は接続用Codexの認証を再利用します。
4. 接続画面を開いたまま、同じPCのDiscordで `/ido agent connect` を選び、**② 参加情報を入力**を押します。接続画面と同じブラウザ・同じプロファイルで開くと、Botの接続先と自分の参加コードが入力されます。**接続画面を表示**を押すか、ブラウザのタブ一覧から接続画面に戻ります。スマートフォンや別のPCからこのリンクを開いても作業PCには届きません。
5. 作業対象のフォルダーを選び、**エージェントを接続**を押します。「接続中」と表示されればタスクを受け取れます。

初回認証時にブラウザが自動で開かない場合は、画面の「認証ページが開かなければ、ここをクリック」を使ってください。このリンクも公式Codexが発行するOpenAIのURLです。

配布ファイルには接続クライアントのソースと依存関係の定義だけを同梱します。Botの設定・秘密鍵・参加情報・実行履歴は含みません。実行可能なファイルなので、自分が参加するチームのBotから取得してください。更新時は既存の接続アプリを終了してから、新しくダウンロードしたファイルを開きます。開発者がclone済みの環境では、従来の `Start Agent.cmd` も使えます。

自動入力リンクは各自のPCの `http://127.0.0.1:17879/join` を開きます。接続アプリを起動していないとページを開けません。接続画面を閉じている・別のブラウザを使っている場合は反映できません。リンクが使えない場合やボタンがない場合は、Discordに自分だけに表示された `ido1.` から始まる参加情報を接続画面の「Discordの参加情報」に貼り付け、**読み込む**を押してください。接続アプリはPCごとに1つ起動し、最初の接続画面を残してください。

リンクには短時間で失効する1回限りの参加情報が含まれます。他人に共有しないでください。参加情報はURLの `#` 以降で渡し、読み取り後はアドレス欄から取り除きます。HTTPのリクエストURLやReferer、参加ガイドのサイトへは送らず、端末の設定ファイルにも保存しません。接続画面は本人のPCのAPIで参加情報を検証し、実際の接続時にBotへ参加コードを送ります。Discord自体はこのリンクを扱うため、OpenAIの認証情報やローカル画面の操作キーは含めません。リンクを開いてもログイン・接続・実行は始まりません。作業フォルダーと権限は本人が選び、自動入力時は実行・外部通信の許可を未選択に戻します。接続中の設定は上書きしません。

次回は起動ファイルから画面を開き、参加コードを空欄にして再接続できます。接続先を変更する場合は新しい参加コードが必要です。既存の認証情報を別のサーバーへ送りません。

既定ではタスクを受け取ってもすぐに実行しません。この画面に表示された依頼を確認して**このタスクを実行**を押してください。90秒以内に確認できない場合や**実行しない**を選んだ場合は実行しません。同じIssueへの追加指示も、その都度確認します。

信頼できるチームのタスクを自動で受ける場合は、接続前に**この接続中は、選んだリポジトリのタスクを自動実行する**を選べます。タスクのシェルからの外部通信とライブWeb検索は既定で無効です。依存取得などが必要な場合だけ**外部通信を許可する**を選んでください。これらの許可は設定ファイルへ保存しません。OpenAIとのモデル通信とBotとの連絡は、タスクの外部通信設定とは別に行います。

接続中はPCと接続アプリを起動したままにします。ブラウザのページを閉じてもWorkerは動き続けます。離席時は**接続を停止**を押してください。登録自体を失効させる場合はDiscordの `/ido agent disconnect` を使います。これでOpenAIからログアウトするわけではありません。

macOS/Linuxのデスクトップ環境でも `npm ci` 後に `npm run agent:ui` で同じ画面を使えます。フォルダーパスは画面に入力します。現時点でダブルクリック起動ファイルとフォルダー選択ダイアログはWindows向けです。

## DiscordからIssueタスクを作成・停止する

参加条件（必要に応じてサーバーの役職）を満たし、自分のエージェントを登録した参加者は、`/ido task` で依頼を送れます。Bot内部にIssueタスクを登録し、設定済みのDiscord Forumに対応スレッドを作成します。これはGitHub Issueを自動作成する操作ではありません。

一般参加者の音声・通常の会話から、発言者本人のエージェントへIssueを作成する経路は未対応です。本人への割り当ては上記コマンドを使ってください。既存の操作担当者向けの会話タスク化とは別の機能です。

各参加者の依頼は本人のエージェントで実行します。切断中は待機し、他人のPCやBotホストへ自動で振り替えません。接続画面でタスクごとに実行を確認するか、接続前に自動実行を明示的に選んでください。

自分のタスクは `/ido stop` でIDを指定するか、スレッド内の停止ボタンで停止できます。Issueスレッドに停止指示を書いても停止できます。停止は待機中の依頼にも実行中のエージェントにも伝わります。参加条件を失った後も、自分のタスクの停止は可能です。他人のタスクやBot全体の操作は、設定済みの操作担当者に限定します。

## 認証と作業場所

- OpenAIの認証は同梱の公式Codexが行い、認証情報はそのPCの接続用 `codex-home` に残します。この接続アプリはパスワード入力欄を持たず、認証ファイルも読みません。接続用Codexでは個人のユーザー設定を共有せず、Apps・フック・プラグインなどの自動利用も無効にします。
- Botとの接続鍵は別物です。WindowsではCurrentUser DPAPI、Linuxでは所有者だけが読めるファイルへ保存します。中央Botには公開鍵と接続トークンのハッシュだけが残ります。
- 接続先、作業フォルダー、表示名は端末内のアプリ設定に保存します。参加コードや認証情報はそこへ保存しません。
- 作業は指定したリポジトリの分離worktreeで実行します。GitHubへのアクセスが必要なら各自のGit認証も事前に用意してください。Botへの参加だけで他人のリポジトリ権限は付与されません。

公式の認証方式は[OpenAIのCodex認証ガイド](https://developers.openai.com/codex/auth/)を参照してください。

CLIから直接接続する場合は `--allow-automatic` または `PERSONAL_CONTEXT_AGENT_ALLOW_AUTOMATIC=true` による自動実行への明示的な同意が必要です。CLIは `CODEX_HOME` の認証を使用します。本人確認を挟んで実行したい場合はWeb画面を使ってください。

## 主催者が用意する接続先

別のPCから参加するには、Bot側のWorker Gatewayへインターネットから届く `wss://` 接続先が必要です。これはタスク・進捗・回答の暗号化された通信路であり、OpenAIへのログイン先ではありません。参加者側にVPNの導入は必要ありません。

主催者のPCを使う場合は、[PC運用の構成](discord-agent-public-deployment.md#主催者のpcで運用する)に沿ってGatewayだけをトンネル経由で接続します。公開サーバーを使う場合はHTTPSリバースプロキシから同じホストの `127.0.0.1:8787` へWebSocketを転送します。どちらもBotのローカル設定には次を指定します。

```dotenv
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_ENABLED=true
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_HOST=127.0.0.1
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_PORT=8787
PERSONAL_CONTEXT_VOICE_WORKER_GATEWAY_PUBLIC_URL=wss://agents.example.com/workers
PERSONAL_CONTEXT_VOICE_AGENT_JOIN_GUIDE_URL=https://example.com/agent-join
PERSONAL_CONTEXT_VOICE_WORKER_ALLOW_GUILD_MEMBERS=true
PERSONAL_CONTEXT_VOICE_WORKER_ENROLLMENT_ROLE_IDS=
PERSONAL_CONTEXT_VOICE_ALL_PARTICIPANTS_OPERATE=false
PERSONAL_CONTEXT_VOICE_AUTONOMOUS_TASKS=false
PERSONAL_CONTEXT_VOICE_CODEX_SANDBOX=workspace-write
PERSONAL_CONTEXT_VOICE_OPERATOR_IDS=<Bot全体の作業操作を許可する担当者ID。不要なら空欄>
```

`agents.example.com` は実際の公開接続先に置き換えます。プロキシはWebSocket Upgradeと長時間接続を許可し、公開側では有効なTLS証明書を使ってください。公開対象はWorker Gatewayだけです。参加者用のローカル接続画面やCodexの認証コールバックを公開してはいけません。

公開先のDNS・証明書・プロキシ設定はホストごとに必要です。このリポジトリだけで公開URLが発行されるわけではありません。Botを起動してから実際に異なるPCの2人が接続し、個別のタスク配信・再接続・登録解除を確認してください。

[公開運用の境界と設定例](discord-agent-public-deployment.md)も確認してください。公開URLを指定した状態で、参加者全員の無条件操作・ホストのsandbox無効化・自律的タスク作成を有効にすると起動を拒否します。
