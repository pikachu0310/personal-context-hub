# Clientの本人識別と再起動

ブラウザーで開くClientとIDO Agentデスクトップアプリは、同じOSユーザーの
`dataDirectory("client")`を使用します。既定の保存先はOSのアプリケーションデータ
ディレクトリー内の`ido/client`です。`IDO_DATA_DIR`を指定した起動は、その保存先を
独立したClientとして扱います。接続画面に現在の保存先と端末IDを表示します。

## 保存するもの

- `client.json`: Engineの接続先、端末ID、プロフィール、設定、ペアリング待ちのIDと期限。
- Credentials: 端末の秘密鍵、期限付きペアリングの証明。証明は終了・失効後に消去します。
- `codex/`: Client専用の公式Codexログイン・設定。普段のCodexの認証ファイルをコピーしません。

通常の終了・再起動やブラウザーの保存領域の削除では、本人情報を作り直しません。
鍵は初回だけ生成します。公開鍵だけが欠けた場合は秘密鍵から復元し、秘密鍵の欠落・
鍵の不一致・JSONの破損では停止します。その場合は同じ保存先のバックアップを復元し、
設定ファイルだけを削除して回復しようとしないでください。
データディレクトリーの移動や別端末へのコピーによる本人移行は今回の対象外です。

## 接続の復帰

Engineの承認後、結果はペアリングの期限内（5分間）なら再取得できます。
通信が切れたりClientが終了した場合も、保存済みの要求から再開します。
期限を過ぎた場合は再度接続を承認してください。
同じEngineユーザーと同じ端末公開鍵で承認すると、有効な既存端末IDを再利用します。
候補が複数ある場合は承認画面で復元するIDを選びます。
失効した端末IDは再利用しません。新たな明示的承認で新規登録しても、失効済み登録の
プロジェクト権限・実行許可は移しません。

## 過去の参加者表示

Engineは、自身の永続名前空間・承認ユーザー・正規化した端末公開鍵から表示専用の
`identityId`を計算します。同じ鍵の重複登録は、タスクのアバターや参加者一覧で
同じ本人としてまとめます。名前だけが同じ人、別の鍵、別のEngineユーザーはまとめません。
同じ本人の過去の端末登録に残る共有タスクは「自分の以前の登録」に表示します。
過去のタスク・発言の原本IDは変更せず、元の`deviceId`で権限・実行先を判定します。
複数の登録をまとめて表示しても、削除操作は端末IDごとに行います。
未対応Engineと接続するときは従来の端末IDによる表示へ戻ります。

## Codexログインの確認

起動・公式ログイン完了・手動確認でApp Serverの`account/read`を使います。
認証方式と、取得できる場合のメールアドレスをローカル画面だけに表示します。
取得できなかった状態と未ログインを区別し、Clientの本人IDを変更しません。
アカウント情報はEngineに送らず、Codexアカウントによる端末間の自動統合は行いません。
仕様: [Codex App Server](https://learn.chatgpt.com/docs/app-server#auth-endpoints)。

検証は`npm run verify`、`npm run smoke:ido`、デスクトップビルド後の
`npm run smoke:desktop`で行います。追加したidentityテストは一時ディレクトリーと
合成アカウントだけを使い、実際のログインや実タスクの実行を要求しません。
