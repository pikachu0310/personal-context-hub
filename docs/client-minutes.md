# ClientのMarkdown議事録

Client／Desktopのプロジェクト内「議事録」は、議題別の要点・根拠発言、
編集できる議事録、発言ログを切り替えて表示する。
「編集できる議事録」は進行中・過去の会話の `summary` 文字列を
CommonMark＋GFMで表示する。既存データの変換は不要。
見出し、リスト、チェックリスト、表、引用、コードに対応し、生HTMLは無効。
画像は外部リンクとして表示し、読み込み時に外部画像を取得しない。
Dashboard・Activity、元の発言ログ、タスクの成果物表示は変更しない。

## 編集とタスク参照

「編集」で単一のライブプレビューを開き、保存またはキャンセルする。
選択中の行だけMarkdownの原文を表示し、そのほかの行は整形する。
複数行を選択した場合は選択範囲の各行を原文表示する。改行・行結合・
Undo/Redo・日本語入力はCodeMirrorで処理し、見た目の変換は保存する本文を変更しない。
「タスクリンクを挿入」から、参加しているプロジェクトとタスクを検索する。

```markdown
[タスク名](ido://projects/<projectId>/tasks/<taskId>)
```

IDは既存のID規則（英数字、`_`、`-`、最大100文字）に従う。
書式の生成・解析は `@ido/common/contracts/api` の
`taskMarkdown`、`taskUrl`、`parseTaskUrl` に集約している。
特殊リンクはClient内で処理し、OSへのプロトコル登録は行わない。
クリック時にEngineのプロジェクト情報を取得し、所属・タスクとプロジェクトの
対応を確認して既存のタスク詳細へ移動する。削除済み・アクセス不可の参照は
エラーを表示し、ほかのタスクへ移動しない。

## 保存と自動更新

Clientの `POST /api/project/minutes/update` は、認証済み接続の
`project.minutes.update` 操作に転送する。
入力型は `MinutesUpdateInput`（`projectId`、`meetingId`、`markdown`、
`expectedRevision`）。本文は最大100,000文字で、空文字と末尾改行も保存できる。
Engineは端末の承認状態、プロジェクト所属、ユーザーの編集権限を確認する。

`summaryRevision` は未設定なら0。手動保存と自動生成のどちらも、保存ごとに
リビジョンを増やして `summaryUpdatedAt` を更新する。
比較に失敗した手動保存は `MINUTES_CONFLICT` を返す。Clientは入力を保持し、
最新版を表示して確認・再編集を促す。定期取得、保存失敗、接続の中断でも
編集中の本文を保持する。ページを移動・閉じるときは未保存変更の破棄を確認する。

自動生成は会話単位で直列化し、最新の本文と追加・訂正された発言を統合する。
議題の更新は `knowledge` に保存し、手動編集された `summary` を直接置き換えない。
会話の処理がまとまった時点で、議事録の生成処理が議題も参照して本文を更新する。
Engineに設定されたOpenAI接続を使う専用の議事録生成で、タスク操作は行わない。
1回に最大30件の発言を処理し、残りは続けて処理する。処理済みの発言は
IDと内容のハッシュだけを記録し、再送や音声認識の訂正を識別する。
タスク参照の生成には、該当会話から作られた実在するタスクだけを渡す。

生成中に手動編集されたら古い結果を捨て、最新本文で再生成する。
連続して5回競合した場合や生成が失敗した場合、保存済み本文を維持して
`summaryState: failed` を表示する。次の会話更新で再試行する。
プロジェクトのコンテキスト初期化、削除、Engine終了後の遅延結果は保存しない。
AIによる統合では表現が変わる場合があるが、手動編集済みの決定・構成・リンクを
引き継ぐよう指示する。

## 検証

Node 24で関連パッケージの `verify:ido` と `lint` を実行する。
Clientをビルドした後の `npm run smoke:minutes` は一時Clientとテストデータを使い、
Markdown描画、タスク遷移、キーボード、編集・挿入、モバイル、保存競合、
通信失敗・再接続、保存後の再読込、閲覧専用表示をブラウザで検証する。
スクリーンショットはignoredの `.ido-build/screenshots/minutes-*.png` に出力する。
