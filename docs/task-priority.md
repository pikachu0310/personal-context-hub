# 会議タスクの評価と配布

議題・候補の抽出は主モデルの一回の応答で行い、同じ応答に採点を含めます。評価専用のモデル呼び出しはありません。計算と閾値は `packages/engine/src/processing/tasks/priority.ts` に集約しています。数値は初期運用値であり、実測済みの確率ではありません。

| 観点                                   | 範囲       | 重み |
| -------------------------------------- | ---------- | ---- |
| 即時性                                 | 0〜4の整数 | 25%  |
| 確実性（今その作業を求めている確かさ） | 0〜4の整数 | 35%  |
| 重要性                                 | 0〜4の整数 | 25%  |
| 具体性                                 | 0〜4の整数 | 15%  |

解決状況は未解決・解決済み・不明で保持し、点数に混ぜません。各観点に短い理由と発言IDを付けます。加重平均を100点に換算し、調査25点、実装・試作・テスト・ベンチマーク40点を初期閾値とします。具体性2以上で確実性4の明示依頼には80点の下限を設けます。解決済み・対象不明・明示的な禁止や保留は開始しません。不明は解決済みと扱わず、新たな再検証依頼は別の意図として評価します。

対象と最小の成果が分かる疑問・比較・検証・実装案を積極的にタスク候補へ切り出します。独立した成果は別タスクにし、依存する実装は調査結果を待って判断します。仕様全体の確定や明示依頼を候補提出の必須条件にしません。

Bot名、コマンド、`interaction: true` は入口の必須条件ではありません。モデルは意図を判定し、Engineは現在の発言ID、発話の完結、引用、操作者・プロジェクトの権限を検証します。「カード形式はどうかな」のような具体案も評価します。評価欠落・不正と低得点を区別し、新しい未評価候補は配布しません。無関係な回答や議事録更新は続けます。

Clientの同時実行は初期値・上限とも4枠です。プロジェクトごとのworktree実行も初期値4枠とし、複数プロジェクト合計でClientの4枠を共有します。保存先を直接編集するproject実行は1枠です。既存の1〜4枠の設定は保持し、4を超える設定は4へ制限します。

配布は優先度の降順、同点は受付時刻順です。実行枠・ネットワーク・実行ポリシー・プロジェクト権限の検証は維持します。1応答最大8案、プロジェクトごとに未割当の先行実行タスク最大8件とし、明示依頼はこの上限に含めません。低得点や上限により見送った候補は採否ログに保存し、直近の候補概要を主モデルへ参考情報として渡します。新しい関連発言があった場合に再提案し、タイマーだけで再評価しません。

関連発言・方針変更・解決・結果イベントで既存タスクを再評価します。待機順を更新し、解決済み・保留・閾値未満の待機タスクは配布を抑止します。評価低下だけで実行中のタスクを中断しません。明示的な停止は既存の停止処理を使います。重複は既存タスクの評価・依頼状態へ反映し、別の作業を増やしません。評価は実行版、操作版、評価版を照合して保存し、古い応答を破棄します。

実行と通知は別です。先行実行の受付は通知しません。結果イベントでは最新の会話から再評価を得たものだけ通知でき、明示依頼・未解決・実行可能・通知閾値70点以上を初期条件にします。解決済みや求められていない結果は文字・音声の双方を控えます。発話準備中に評価が変わった場合も再生前に確認します。Liveの直接回答を主モデルが重複発話しない既存の境界を維持します。

全タスクの結果は通知の有無に関係なく議事録生成へ独立した入力として渡します。失敗・停止・中断の部分成果と未確認事項も対象です。1回最大4片、各4000文字で順次反映し、タスク・実行ID・実行版ごとの本文指紋と処理位置を永続化します。原文はタスクに保持します。生成には完了前も含む会議タスクの依頼内容・状態・根拠発言IDを渡し、タスクとの紐付けを最優先します。タスクごとに背景・要点、決定事項、未決事項、作業結果をまとめ、末尾の一覧だけでなく本文の各記述のそばにタスクリンクを置きます。タスク未紐付けの議題も残します。既存の手動編集を尊重し、Botの成果を人の合意と扱わず、依頼内容を検証済みの結果と混同しません。手動編集や結果の変更との競合時は最新本文で再生成します。議事録本文と処理位置は同じトランザクションで保存します。

既存タスクは明示依頼80点、先行調査40点、その他の先行作業60点の互換優先度で扱い、関連する会話・結果イベントで新評価へ移行します。更新前に保存された応答は従来の受付制限で再開します。履歴を一括再送したり、評価移行のために作業を再実行したりしません。文字配送の試行記録と結果イベントIDによる再送抑制も維持します。

テストは固定した主モデル応答でEngineの計算・認可・連続受付・通知・再開と議事録競合を検証します。実モデルの採点品質、議題抽出精度、運用閾値の適切さはこの模擬テストでは測定していません。
