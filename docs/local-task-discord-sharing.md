# ローカルタスクをDiscordのissueフォーラムへ共有する

プロジェクト名のメニューから「このPCでタスクを開始」を開く。
「Discordにも共有」は初期状態でONで、開いたプロジェクトが共有先に選ばれる。
モデル、作業フォルダー、依頼内容、進め方を確認して開始する。
共有チェックを外すと、そのタスクはPC内だけで実行する。

共有先のEngineとClientは、この機能に対応する同じリリースを使う。
EngineのDiscord設定で、対象プロジェクトとissueフォーラムを指定し、Botを接続する。
現在のDiscordアダプターは、設定された一つのプロジェクトとフォーラムを同期する。
別プロジェクトを選んだ場合は共有待ちになり、アプリに設定不足を表示する。

## 共有する情報と操作

- タスク名、開始時の依頼文、実行状態（相談中・実行待ち・実行中・完了・失敗・停止）を送る。
- Discordには実行ログ、モデルの回答、差分、認証情報、作業フォルダーのメタデータは投稿しない。
- Engineにはタスク画面の詳細履歴も同期する。同じプロジェクトの参加者は、Codex未ログインでも会話、コマンド出力、変更、実行環境、エージェントに渡したソースをアプリから閲覧できる。詳細は[共有タスクの履歴](shared-task-history.md)を参照。
- Discordスレッドへのメッセージは追加指示になる。`停止`、`中止`、`キャンセル`、`stop`、`cancel`で停止する。
- Discordの既存の参加者・役割制限を適用する。Manualの実装開始と追加権限の承認は、作成者のアプリで行う。
- 終了後の再実行は作成者のアプリから行い、同じ共有タスクとスレッドへ新しい実行状態を送る。

## 再接続と重複防止

タスクは作成元PCが実行し、Engineには共有用の記録を作る。共有用記録は通常の割当キューへ入れない。
共有先Engine・端末ID・プロジェクトはタスク作成時に保存する。他の接続先へ変更しても、その共有待ち情報は転送しない。
端末IDとローカル実行IDから共有タスクIDを決定し、更新には増加する番号を付ける。応答が失われても同じ記録へ再送する。
Discordスレッドの重複防止は既存のフォーラム同期処理を利用する。

Clientは接続中に約5秒間隔、Discordアダプターは約10秒間隔で同期する。
「共有登録済み」はEngineが受理した状態であり、Discordへの投稿完了通知ではない。
未接続・旧Engine・フォーラム未設定のときは、ローカル実行を続けつつ共有待ちと理由を表示する。
既存の共有していないローカルタスクを、自動的に共有へ変更することはない。
