# IDO Dashboard

`/dashboard/` は管理者向けの運用画面です。タスク、割当ユーザ、実行エージェント、
プロジェクトへの所属と接続状況、会話量を俯瞰できます。
会話送信・タスク作成・追加指示はClientが担当します。Dashboardには入力・作成・編集のUIを置きません。
接続設定、認証、プラグイン起動は左下の「接続・エンジン設定」から `/admin` を開きます。

## 画面

- **概要**: 現在の実行／待機タスク数、接続中ユーザ数、稼働中会話数、プロジェクト数。
  タスクのルーティング表、参加者一覧、直近60分の発言数を表示します。
- **タスク**: 名前・ID・状態で検索し、右側の詳細から停止できます。実行版、割当理由、
  待機理由、作成・割当・最終更新時刻、発生元の会話と操作履歴への導線があります。
- **ユーザ・接続**: 登録ユーザとその実行端末を区別します。接続ごとの詳細から一時切断できます。
- **プロジェクト**: 所属ユーザと現在接続中のユーザ、関連する会話とタスクを確認できます。
- **生データ**: 会話、議事録、管理操作イベントの閲覧。期間・対象IDで絞り込み、50件単位で取得します。
  本文は最大16,000文字、既知の資格情報パターンを伏せます。SDK生出力・設定・秘密情報は返しません。

日時はブラウザのローカル時間で表示します。表は狭い画面では横スクロールし、ナビゲーションはメニューに収めます。
ReactとMantine 9.6.1のAppShell、Table、Drawer、Modal、Select、Pagination等を使用します。

## 集計の定義

実行中は `running`、待機は未割当の `queued` と実行開始待ちの `assigned`。
中断・失敗・停止要求中は状態名で区別します。件数はイベントの保持件数ではなく、サーバーのタスク台帳を基準にします。

接続中ユーザは認証済みClient接続の所有アカウントIDで重複除去します。
複数端末を持つ人は1人と数えます。接続していない登録端末も所属の確認用に残します。
会話のみの参加者や端末プロフィール名を別の登録ユーザとして推測しません。
所属は失効していない登録端末の `project-member` を所有アカウントへ対応付けます。

稼働中の会話は「現在のプロジェクト会話のうち、直近5分に人の発言があり、閉じていないもの」。
発言数は保存済みの人のメッセージで、本文があり、未確定とされていないレコードを5分刻みで集計します。
アシスタントの発言は含みません。サーバーの保持範囲を併記し、不足期間を観測済みとして扱いません。
従来のタスクに割当時刻・理由がない場合は「未取得」と表示します。

## 停止と一時切断

タスク停止はタスクID・実行ID・実行版・制御版を照合し、既存の停止受付へ接続します。
未割当タスクはエンジンで停止確認できます。割当済みタスクはClientの停止レシートが届くまで
「停止要求中」です。POSTの受付成功だけで実行終了と表示しません。同じ要求IDの再送で停止を重複作成しません。

接続切断は端末ID・接続世代・対象の進行中タスク一覧を照合します。
一覧をプロジェクトで絞っていても、切断確認はその接続の全プロジェクトの影響を読み直します。
確認中に対象の実行版・制御版・タスク構成が変わると409で再確認を要求します。

対象接続への新しい割当を止め、進行中タスクへ停止を送り、最大3秒間停止確認を待ってから
その接続だけを閉じます。停止応答がなければ「停止未確認」と結果・操作履歴へ記録します。
これは到達不能な端末のプロセスを強制終了できたという保証ではありません。
未割当の待機タスク、ユーザ登録、プロジェクト所属、端末鍵は保持します。
停止対象の古いexecute/retryは再接続時に再配送しません。

対応Clientは切断コード4004を受けると、その接続のリモート実行に停止を要求し、自動再接続を休止します。
ユーザによる通常の再接続は可能です。ローカルタスクを巻き込みません。
旧Clientにも通常の停止コマンドを送りますが、4004に対応しない版は自動再接続する場合があります。
古い接続の切断処理から、新しい接続を閉じることはありません。

## APIと互換性

以下はすべて既存の管理セッションで認証し、adminロールに限定します。POSTは既存のHost/Origin検査とCSRF検証を適用します。

| API                                                                      | 用途                                                                              |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| GET /api/admin/dashboard?projectId=…                                     | 管理用の限定したスナップショット                                                  |
| GET /api/admin/dashboard/raw?kind=messages&from=…&to=…&target=…&offset=… | 期間内の会話・議事録・操作イベント。kindはmessages/minutes/events                 |
| POST /api/admin/dashboard/stop                                           | taskId, runId, revision, controlVersion, requestIdを指定して停止                  |
| POST /api/admin/dashboard/disconnect                                     | deviceId, generation, tasksの各id/runId/revision/controlVersionを指定して一時切断 |

通信断では最後の表示と最終更新時刻を残し、管理操作を無効化します。401/403では保持中の管理データを画面から除去します。
生データは別リクエストで必要時に取得し、ブラウザストレージへ保存しません。

既存の `/dashboard/api/` のクライアント互換API、`/admin` の設定画面、Client側の共有Workspaceは維持します。
今回変更するのはDashboardのUIと専用管理APIです。データの削除や移行は不要で、既存Taskへの割当情報は任意フィールドです。

## 検証

Node 24で次を実行します。

```sh
npm ci
npm run verify
npm run smoke:dashboard
npm run smoke:ido
```

Dashboardのスモークは隔離したDBと模擬実行Clientを用い、実サービスのアカウントやモデルAPIは利用しません。
概要、切断確認、通信断、1672/1366/390pxの画面を `.ido-build/screenshots/ido-dashboard-*.png` に保存します。
APIテストでは権限、CSRF、古い操作拒否、重複停止、割当・件数、停止確認待ち、一時切断、
接続置換競合、停止未確認、再接続、ローカルタスクの保持を検証します。

## 管理者による完全削除

プロジェクト・タスクの一覧は行全体から詳細ドロワーを開けます。名前ボタンはキーボードでも操作できます。
タスク詳細の「タスクを強制削除」は、未割当・実行中・実行先未接続・停止確認待ちを含む全状態で利用できます。
通常プロジェクトは、名前を入力して確認すると配下の全タスク・議事録・関連履歴も削除します。デフォルトプロジェクトは削除できません。
削除成功後は詳細を閉じて一覧を更新し、削除したプロジェクトの絞り込みを解除します。

管理用の `POST /api/admin/dashboard/task/delete` と `POST /api/admin/dashboard/project/delete` は任意の `force: true` に対応します。
タスクは `taskId`, `revision`, `controlVersion`, `membershipVersion`, `confirm: true`、プロジェクトは `projectId`, `name`, `membershipVersion`, `confirm: true` を指定します。
`force` を省略した場合は従来どおり実行中・停止確認待ちの削除を拒否します。強制指定でも管理者権限・確認入力・バージョン照合は必須です。

Engine側の削除はClientの停止応答を待ちません。対応Clientには既存の `task.purge` を配送して実行中断と履歴整理を行い、オフライン端末は再接続後に反映します。
削除同期に未対応の旧Clientは同期待ちとして残ります。Gitフォルダと外部サービスの投稿は保持します。
削除記録により遅延結果や古い実行コマンドからの復活を防ぎます。共通UIの `forceDelete` 設定は既定で無効で、管理dashboardのみ有効にします。
