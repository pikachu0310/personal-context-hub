# 音声エンジンのライブHUD

Issue #10 の閲覧専用HUDです。React / TypeScript / Vite / Tailwind CSS と
shadcn/ui形式のRadix Switchを使用し、フローとタイムラインをSVGで表示します。
実データの到着前に架空の会話やタスクを表示しません。

## 起動

```bash
npm ci
npm run hud:install
npm run hud:build
PERSONAL_CONTEXT_VOICE_HUD_PORT=4310 npm run start:discord:voice
```

既に設定済みの音声runtimeを通常どおり起動してください。この変数を省略するとHUDは
起動しません。`http://127.0.0.1:4310` を同じ端末のブラウザで開きます。
`localhost`の別名・LANアドレス・リバースプロキシ・リモート公開は対応しません。
ポート番号は変更できます。組み込みでは `config.hudPort` を指定でき、`0` はOSの
空きポートを使用します。実際のURLはruntimeの起動ログに出ます。

HUDの起動失敗やブラウザ切断は音声エンジンを停止しません。
音声サービスの停止時にHUDも終了します。UIの変更後は再ビルドして再読み込みします。

## 表示と操作

- 上部にHUDとの接続状態とタスク実行／待機件数を表示します。
- 左に話者、認識テキスト、応答、関連するタスクを表示します。
- 中央に音声入力、STT、発話組立、会話観測、即時応答、タスク待機／実行、
  配送、TTS、再生の処理区間を表示します。並行区間は別カードになります。
- 発話・タスク・タイムラインの選択が全パネルで連動します。右側でツール名、
  検索クエリ、状態、経過時間、結果概要を確認できます。
- 紫は実行中、琥珀は待機、赤は失敗です。完了・中断・スキップも文字で区別します。
  タイムアウト、実行枠、STT枠、読み上げキュー、話者の発話終了待ちなど、判明した理由を表示します。
- 「本文を隠す」は話者名・会話・タスク名・ツール名・クエリ・概要を全パネルで
  マスクします。表示のみの機能です。配信内容を匿名化したり、ブラウザの開発者ツール
  からデータを消したりする機能ではありません。
- 通信断では最後に受信した状態を残し、古い表示であることを明記します。
  通信断を処理停止に読み替えません。再接続時はsnapshotで同期します。

SDKが提供しないクエリ・結果概要は「未提供」と表示します。推論テキストや
ツールの生入出力から情報を抽出して補いません。通常のSTT/TTS経路は再生完了まで
追跡します。GPT-Live経路の同期的な発話依頼は再生完了を通知しないため、再生完了を
装わず「Live音声の再生完了情報は未提供」と表示します。

## 観測境界

`createConversationEngine({ onEvent })` は任意の受信先を受け取ります。
イベントにはセッションID、発話ID配列、タスクID、実行回ID、処理区間ID、親ID、
段階、状態、時刻を含めます。発話IDは会議IDで名前空間を分け、複数発話の関連を保持します。
並行非同期処理の関連付けはエンジン内のAsyncLocalStorageで管理します。
受信先の例外・Promiseの失敗は処理本体に伝播させません。

実行ポートの `runTask(task, { onProgress, onEvent })` は従来の文章進捗通知を維持し、
構造化コールバックをバックエンドに渡します。Codex SDK / app-serverの
item開始・更新・完了を許可した種類のツールメタデータへ正規化します。
完了のないツールは中断／完了情報未提供として閉じ、無期限に実行中として残しません。

runtimeがHTTPサーバーとメモリ上のリングバッファを所有します。

- `GET /api/snapshot`: 配信セッションID、最新連番、直近最大1,000イベントと、
  履歴とは別に最大1,000件の現在の処理区間（`active`）。長い処理が履歴から押し出されても
  実行中／待機中の状態と開始時刻を保持します。完了時に現在の区間から除去します。
- `GET /api/events?after=N&session=ID`: SSEの `observation` イベント。
  `id` は連番です。`Last-Event-ID` も受け付けます。
- 再開地点が保持範囲外、配信セッションが変更、連番が不正なら `reset` を返します。
- 15秒ごとの `heartbeat` とブラウザ側の35秒監視で無応答も検出します。
- UIは重複を無視し、欠落時はsnapshotを再取得します。過去の非同期接続が
  新しい接続状態を上書きしないよう接続世代を管理します。

サーバーは127.0.0.1だけにbindし、Host・Origin・Fetch Metadataを検査します。
同一オリジンのGETだけを許可し、キャッシュ、外部スクリプト、埋め込みを無効にします。
イベントは許可したフィールドだけを配信し、音声バッファ、SDKの生入出力、認証設定は
配信しません。テキストは長さを制限し、既知の資格情報表現もマスクします。
履歴をファイルやブラウザストレージに保存しません。遅いSSEクライアントは切断して
エンジン側の待機や送信バッファの無制限な増加を避けます。

## 検証

```bash
npm run verify
npm run hud:build
npx playwright install chromium
npm run smoke:discord:voice:hud
npm --prefix ui audit
```

`voice-hud.test.mjs` はエンジン境界、並行入力、配送・音声関連、失敗／中断／タイムアウト、
履歴制限、許可フィールド、HTTP制約、SSE欠落・再接続を確認します。
既存のDiscord mock E2Eも任意起動HUDから処理イベントを取得します。
ブラウザsmokeはテスト内だけで架空データを投入し、選択連動、全本文非表示、
1920×1080 / 1366×768、通信断・1,000件超の欠落からの復旧を確認します。
必要なら `HUD_BROWSER_EXECUTABLE` でブラウザ実行ファイルを指定し、
`HUD_SCREENSHOT_DIRECTORY` でスクリーンショットのローカル出力先を指定できます。
