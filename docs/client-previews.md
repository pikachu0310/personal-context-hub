# 議事録から実装を起動・比較する

議事録の「実装を起動」「2案を比較」をクリックすると、このPCに比較用worktreeを取得する。
「起動」でCodexがREADMEと起動設定を読み、依存関係を準備してWebサーバーを起動する。
起動のためのソース・lockfile修正は行わない。修正が必要な場合や秘密情報が不足する場合は理由を表示する。

## リンクの自動記載

実装元Clientは、完了した共有タスクのGit状態を約15秒ごとに確認する。
未コミット変更がなく、リモートのブランチ・タグから取得可能なコミットをEngineへ登録する。
認証情報を含むURL、ローカルパス、Gitの外部ヘルパープロトコルは登録しない。
Git認証には各PCの既存の設定を使う。秘密情報をリンクやEngineへ保存しない。

議事録生成LLMには会議のタスク結果と登録済み実装を渡す。
画面確認に適した成果は単独起動、同じ議題の代替案は2件比較として自動で記載する。
LLMは `{{preview:実装ID}}` または `{{preview:実装ID,実装ID}}` を選び、Engineが候補との一致を検証してMarkdownリンクへ変換する。
実装情報の更新だけでも議事録生成を再評価する。未pushの成果を古いコミットへ置き換えない。

```markdown
[実装を起動](ido://projects/<projectId>/previews/<implementationId>)
[2案を比較](ido://projects/<projectId>/compare/<leftId>/<rightId>)
```

リンクはコミットに固定され、ブランチの更新後も元の実装を参照する。
新しい成果には別の実装IDを使う。アクセス不可・削除済みタスクの参照は拒否する。
リンクの表示や自動記載では取得・起動しない。特殊リンクはClient内だけで処理する。

人による操作は、議事録編集の「起動・比較リンクを挿入」と、タスク詳細の
「実装を起動・比較」から行う。同一プロジェクト内の1〜2件を選択できる。

## 起動と比較

- 既存のリポジトリ対応付けが取得先と一致すれば利用し、なければClientの管理領域へcloneする。
  指定コミットのdetached worktreeを作り、通常の作業フォルダーを切り替えない。
- Codexの確認作業は既存の実行枠を使う。2件同時に起動を依頼しても、枠が1つなら準備を順番に行う。
  起動後のサーバーはCodexの思考枠を消費しない。
- 準備とサーバーはApp Serverの `command/exec` を使い、worktreeを対象とするサンドボックスで実行する。
  ネット接続の初期値はプロジェクト設定を引き継ぎ、未設定ならOFF。起動画面で変更できる。
  OSのサンドボックスがlocalhostの待受けも制限する場合は、ネット接続をONにして再試行する。
- 操作可能なプレビューと画像比較を切り替える。初期条件は `/`、1280×800。
  「同じ条件で撮影」で対象パスと表示サイズをそろえて再撮影する。ブラウザのログイン状態は共有しない。
- 埋め込み拒否が確認された場合は画像比較または別タブで開く。
  撮影用Chromiumがなければ画面からセットアップする。Client配布にはPlaywrightを含める。
- 停止、比較画面終了、Client終了で所有するプロセスを終了する。
  画面との通信が45秒以上途切れた場合も停止する。別の画面が同じ実装を使用中なら、最後の画面を閉じた時に停止する。
  再起動後の自動実行は行わない。worktreeは保持し、画面から明示的に削除できる。

画像、起動ログ、worktreeのパス、実行ハンドルはローカルに保存する。
プレビューは管理画面と別オリジンで表示する。Desktopと撮影ブラウザは登録済みのプレビューへの通信に限定するため、
外部フォント・外部APIを必要とするページは、その部分を表示できないことがある。

## 契約と検証

Engineは `implementationVersion: 1` を通知する。
`implementations.sync/list/read` で実装情報を登録・参照し、登録時は担当Clientと実行リビジョン、参照時はプロジェクト所属を確認する。
旧Engine・未対応Client・実装情報のない既存タスクには利用できない理由を表示する。

Clientの `/api/previews/` は `prepare/start/stop/state/inspect/capture/release/remove/install-browser` を提供する。
変更操作は既存のOrigin検証とCSRF検証を使い、画像もローカルAPIから取得する。

Node 24で `npm run verify:ido`、`npm run lint`、`npm run smoke:minutes`、`npm run smoke:previews` を実行する。
比較smokeは合成GitリポジトリとCodex応答のテスト代替を使い、実サーバー・Chromiumで操作、撮影、停止を検証する。
`node scripts/preview-codex-smoke.mjs` は固定バージョンの実Codexでサンドボックス内のサーバー起動・停止を確認する。
`node --import tsx scripts/desktop-preview-smoke.mjs` はDesktopの通信制限を適用した実ウィンドウの左右操作と、配布物内のPlaywrightによる撮影を検証する。
モデルへの実リクエストは通常の検証に含めない。
