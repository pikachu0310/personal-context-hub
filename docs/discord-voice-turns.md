# Discord音声の割り込みと再発話

通常の読み上げ（text-speech）とLiveに適用する。しきい値は共通の`VOICE_TIMING`にまとめ、設定画面は追加しない。

| 入力・状態                              | 動作                                                                          |
| --------------------------------------- | ----------------------------------------------------------------------------- |
| 発話開始                                | 新しい再生の開始を待たせる。再生中の音声は継続する                            |
| 同じ話者の信号が1,200ms継続             | Discordで停止し、Engineへ`interrupt`を送る                                    |
| 無音・DC・短いクリック                  | 長い発話として扱わない。300ms以上の無音・パケット間隔で継続時間をリセットする |
| 短い相づちの文字起こし                  | 現在の候補と会話をメインモデルで再評価し、継続可能なら再生を維持する          |
| Botへの明確な停止・訂正                 | 文字起こしと文脈判断後に停止する。引用や参加者同士の会話だけでは停止しない    |
| 中断後、全員が1秒静かで文字起こしも完了 | 今も必要な内容だけ短い回答へ作り直す。解決・撤回・話題変更なら取り消す        |
| 明示的な音声停止コマンド                | 即時停止し、再発話候補も破棄する。背景の作業停止とは別                        |

発話時間は話者別PCMの20msフレームから計算する。音声認識器ではなく、既存STT前処理と同じ信号判定であるため、継続した環境音も割り込みとなり得る。Discordの受信終了までの無音待ちは発話時間へ足さない。終了通知の`silenceMs`で経過済みの無音を引き継ぎ、再発話でさらに1秒待つことを避ける。

## 候補と判断の扱い

音声候補は会話ごとに最新の1件だけをメモリに保持する。候補ID、回答文、根拠の発言・タスク結果、会話の版と状態を持ち、中断から90秒で期限切れとなる。

`speech_review`は既存CoordinatorInboxへ優先投入する。モデルは`speech`に候補ID・会話の版と`continue`、`stop`、`replace`、`discard`を返す。新しい質問への回答も必要なら`replace`の文章へまとめる。再評価のための過去発言は、作業タスクを新たに作成・操作する権限にならない。

新しい発話・文字起こしで判断を無効にし、再生直前にも文脈と接続を確認する。Discord側の`playbackRevision`でも、発話前に送られた古い音声が後から再生を始めることを防ぐ。最終音声区間のRPCより終了通知が先に処理されても、文字起こしを待つ。

判断は同じ候補・会話の版で一度だけ行い、30秒でタイムアウトする。判断欠落・不正なID・失敗時は中断済み音声を再送しない。退出・接続変更・モード変更・権限失効でも破棄し、保存されたCoordinatorの状態には音声再評価イベントを残さない。

## Live

アプリ側の発話開始時の停止と一律の出力破棄を取り除き、再生中のストリームは短い相づち中も続ける。新しいストリームは人の発話中に開始しない。Live提供元自身が音声生成を終了する動作は、アプリ側の停止とは別である。

[OpenAIのLive仕様](https://developers.openai.com/api/reference/typescript/resources/live)では、文字列の断片は完全な発話単位や再生完了を示さない。Live記録の再生状態は未確認のままとし、生成した文章を「聞き終えた文章」とは扱わない。

確定した割り込みでは旧セッションを閉じ、世代番号で遅着音声・文字列・終了コールバックを無効にする。入力と独立した文字起こしは続行し、必要な再発話は最新文脈を持つ新しいLiveセッションから生成する。閉じた理由はLive終了ログの`reason`で区別する。

## 検証

自動検証は共通・Engine・Discordのテスト、型検査、ビルド、lintを実行する。

```sh
IDO_PACKAGES='["common","engine","plugin-discord"]' npm run verify:ido
npm run lint
```

追加テストは、合成PCM・仮想時計による境界判定、相づちの継続、短い停止、再評価中の追加発話、STT完了順序の逆転、期限切れ、古い候補・Liveコールバックの遮断、Coordinatorとの結合と権限制約を扱う。モデルの判断は注入した応答で検証し、意味判断の実環境での精度とは区別する。

実Discordで確認する場合は、通常音声とLiveをそれぞれ選び、次の順で聞こえ方を確認する。

1. Botの説明中に短く「うん」「はい」と言い、アプリが再生を止めないことを確認する。
2. 1.2秒以上話し、しきい値付近で停止することを確認する。
3. 説明が必要な追加質問では全員の無音とSTT確定後に短く話し直し、「解決した」では繰り返さないことを確認する。
4. 「待って」「違う」、同じ語の引用、参加者同士の発言を試し、Bot宛ての意図を区別することを確認する。
5. 複数人で発話をつなぎ、一人が止まっても別の人が話している間は新しい再生を始めないことを確認する。
6. 中断後に音声停止コマンド、退出、モード変更を行い、古い説明が復活しないことを確認する。

実接続と人が聞いた際の自然さは、上記の自動テストだけでは検証できない。
